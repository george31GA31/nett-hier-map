## What is implemented

- Confirmation signup/resend and password reset explicitly target `https://george31ga31.github.io/nett-hier-map/`, including the trailing project path. Confirmation success updates the account panel. Invalid/expired/used callbacks show sign-in/resend guidance and explain old localhost links. Recovery links offer a new password. Callback credentials are removed from the URL.
- All five sticker images use measured artwork bounds and one common canvas envelope. Source images are preserved. Aspect ratios, captions, arrows, indicator and keyboard navigation remain intact.
- Nearby navigation stops the native event **before replacing the DOM**. Previously Leaflet's parent traversal lost the old popup ancestor, letting the click reach the map and close the popup. Stable ordering now also prevents count resets on zoom. Popup sizing constrains controls and allows only vertical scrolling.
- Guests can participate without accounts. New sightings/uploads, reports and private requests go through `public-api`, with server-side Turnstile verification and transactional database quotas. Direct client writes and Storage uploads are revoked. A global pause switch defaults to paused.
- Default quotas: 5 sightings/hour/network hash, 20/day/account, 250/day/site; 10 reports/hour/network hash, 30/day/account, 500/day/site. Upload attempts reserve up to 1 GiB/day/site and check a 4 GiB storage budget. Guest browser IDs cannot bypass the global quota. Rotate the IP HMAC secret only deliberately; even untrusted/spoofed proxy headers cannot bypass site-wide quotas. Confirm gateway header normalization during staging.
- Photos are bounded to 6 MiB, JPEG dimensions to 4000×4000, and metadata-bearing JPEG segments are stripped on the backend too. Photos use unpredictable reservation paths; arbitrary supplied ownership, image URLs and paths are ignored/rejected.
- Moderators are explicit UUIDs in a private table, never user-editable metadata. The owner inbox lists reports and private contact/removal requests, shows storage and cleanup counts, can dismiss reports, remove a sighting/photo or pause submissions. It is checked on the backend for every operation.
- Deletions enqueue the associated bucket-relative photo. The service-only worker checks references before deleting through the Storage API. Failed saves expire after an hour and enter the same worker. Historic orphan candidates are inventory-only; no bulk deletion is implemented or performed.
- Account deletion deletes that account's owned sightings, queues photos, removes its reports, revokes Auth sessions and deletes the Auth user. A private tombstone rejects surviving access tokens; account creation/deletion uses an account lock to avoid racing new sightings. Guest sightings cannot be retrospectively assigned and need a removal request.
- The privacy notice and submission consent describe public nickname, pin, date, note and photo. A private contact form feeds the owner inbox. Existing fan-project and anti-vandalism statements remain.
- Low zoom shows counts; zooming in retains individual pins and nearby navigation. Detail loading uses viewport filtering and keyset pages of 500 until exhausted, inside scalar JSON RPCs so PostgREST's row cap cannot silently truncate a page. Statistics are exact database counters initialized from **all** existing rows, maintained transactionally on changes, and independent of the loaded viewport. Counts refresh every minute; photos are loaded only when opening a sighting.
- Reverse geocoding has one database-backed lease shared by all Edge instances, a 30-day locality cache and a minimum 1.1-second gap **after** each upstream response. A crashed lease stays closed rather than risking concurrent requests; coordinates still save. OpenStreetMap attribution remains.
- Separate encrypted database/photo backup workflows and hourly cleanup/moderation/storage alerts are committed, disabled until configured. Storage request-count monitoring uses the documented Management API. **Request counts are not bandwidth bytes:** authoritative cached/uncached egress and billing alerts must still be configured/viewed in Supabase Usage/Observability.
